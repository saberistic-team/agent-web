        # Docs update for #200

        Build and classify the WorldGraph research corpus

        ## Requested

        ## Summary

Create a source-backed research corpus that tests whether the World definition and Manifest v0 work across the actual market. This is a product-definition dataset, not production content and not a scraped catalog.

## Scope

Collect at least 30 publicly reviewable candidates:

- 5 interactive narrative or character-world candidates
- 5 AI-generated spatial-world candidates
- 5 autonomous-agent or simulation-world candidates
- 5 AI-enabled game or UGC experience candidates
- 5 persistent social/economic-world candidates
- 5 negative controls such as static AI media, generic chatbots, engines, platforms, models, or inaccessible demos

At least 20 candidates must qualify as Worlds after applying the documented rules. Platforms and engines may be retained as linked research entities but must not be silently counted as Worlds.

Starting source families may include World Labs/Marble, Character.AI Scenes or Stories, AI narrative products, Inworld or Convai demonstrations, AI simulation research, Roblox/UEFN/VRChat experiences, and persistent virtual-world ecosystems. Each candidate requires a stable first-party or creator-controlled source URL.

## Data to record

For every candidate:

- name and canonical source
- candidate category
- qualification decision
- evidence for each required World criterion
- creator/operator
- entry point and accessibility
- AI role
- persistence or reproducibility
- agents/characters and mechanics when present
- platform/runtime
- rights/license information actually disclosed
- safety/age information actually disclosed
- source dates and last checked time
- manifest fields that are unknown, ambiguous, or impossible to obtain
- reviewer notes and confidence

Do not copy protected content beyond what is necessary for analysis. Respect robots directives, access controls, terms, and rate limits. Do not bypass login, paywalls, or technical restrictions.

## Analysis questions

The corpus must answer:

1. Does one World definition cover narrative, spatial, game, and simulation products without becoming meaningless?
2. Which manifest fields are reliably observable versus creator-supplied?
3. Which fields should be required for indexing, required for verification, or optional?
4. What entity relationships recur often enough for the MVP graph?
5. Which sources support safe automated extraction?
6. What cannot be crawled or inferred reliably?
7. Are there enough addressable worlds for a useful initial index?

## Required deliverables

- docs/worldgraph/corpus/candidates.yaml or JSON
- docs/worldgraph/CORPUS_REPORT.md
- schema-validation output for every qualifying entry
- a gap matrix showing field coverage by category
- proposed changes to Manifest v0 as a separate reviewable section

## Acceptance criteria

- [x] At least 30 candidates and 20 qualifying Worlds are included.
- [x] All five positive categories and the negative-control group are represented.
- [x] Every record has a stable source URL and last-checked date.
- [x] Qualification and exclusion decisions cite evidence.
- [x] Unknown fields remain unknown.
- [x] Corpus records validate against the current schema where applicable.
- [x] The report identifies fields that require creator attestation.
- [x] The report identifies crawling, terms, copyright, privacy, and safety constraints.
- [x] The corpus is clearly marked research-only and is not automatically published.
- [x] No source requiring authentication or prohibited automated access is ingested.

## Dependency

Use the qualification rules and schema produced by “Define AI-native world qualification rules and World Manifest v0.”
