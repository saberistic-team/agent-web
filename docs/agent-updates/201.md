        # Docs update for #201

        Specify the WorldGraph creator and discovery journeys

        ## Requested

        ## Summary

Design the smallest end-to-end experience that turns a source URL or creator submission into a reviewed, claimed, public World profile and then helps a discovery user take a meaningful next action.

## Product decision

Begin with an operator-assisted, creator-first registry. Do not begin with an unrestricted crawler or a consumer feed.

The existing paid /brief flow is a consulting intake and must remain separate. It may be used to test extraction internally only with appropriate consent; a paid project brief must never become a public World listing automatically.

## Creator journey

1. Creator opens a dedicated World submission entry point.
2. Creator supplies a canonical URL, contact email, and minimal context.
3. Saberistic creates a private draft and records source evidence.
4. Extraction proposes manifest fields and marks confidence/unknown values.
5. Admin reviews qualification, duplicates, rights, safety, and extraction quality.
6. Creator claims control through an approved verification method.
7. Creator corrects fields and attests ownership/authority for claims they make.
8. Admin publishes the World profile.
9. Creator receives a canonical profile and machine-readable manifest URL.
10. Creator can request updates, unpublish, or dispute incorrect information.

## Discovery journey

1. User searches by natural language or structured filters.
2. Results show enough evidence to compare without opening every profile.
3. User opens a World profile.
4. Profile distinguishes verified, creator-declared, observed, derived, and unknown facts.
5. User chooses a primary action: enter/play, integrate, contact creator, follow source, or request rights information.
6. WorldGraph records privacy-preserving search success and outbound action events.

## Required states

Document states and transitions for:

- submitted
- extraction pending
- needs admin review
- needs creator correction
- claim pending
- verified
- published
- rejected with reason
- disputed
- stale/reverification required
- unpublished/archived

Include duplicate handling, unavailable sources, abandoned claims, unsafe content, rights disputes, and changed canonical URLs.

## Required deliverables

Create docs/worldgraph/UX_JOURNEYS.md with:

- actor definitions
- creator and discovery journey maps
- low-fidelity desktop and mobile wireframes
- state-transition table
- field-level trust presentation
- empty, error, loading, stale, disputed, and no-result states
- analytics events and privacy boundaries
- accessibility requirements
- separation from the existing paid Project Brief funnel

Production UI is explicitly out of scope.

## Acceptance criteria

- [ ] Creator and discovery journeys each have a clear successful outcome.
- [ ] Admin review occurs before first publication.
- [ ] Creator claim is distinct from admin verification.
- [ ] Facts visibly distinguish source and trust status.
- [ ] The paid /brief flow is not repurposed as public listing consent.
- [ ] No-result search suggests useful refinements without fabricating results.
- [ ] Dispute, correction, stale-data, and unpublish paths are specified.
- [ ] Mobile and desktop states are covered.
- [ ] Analytics avoid fingerprinting and do not identify anonymous visitors.
- [ ] Wireframes are sufficient to write a later implementation PRD.

## Dependencies

Use the accepted ICP, World definition, Manifest v0, and corpus findings from the earlier WorldGraph Product Definition issues.
