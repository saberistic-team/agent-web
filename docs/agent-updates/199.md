        # Docs update for #199

        Define AI-native world qualification rules and World Manifest v0

        ## Requested

        ## Summary

Define the primary object WorldGraph indexes and specify a versioned World Manifest v0 that can represent real projects without collapsing platforms, tools, characters, and static AI media into one vague category.

## Product decision

For the MVP, an **AI-native world** is an addressable interactive system that is persistent or reproducible, has a bounded setting or rule system, permits users or agents to affect outcomes, and uses AI materially in the environment, characters, narrative, simulation, or runtime behavior.

A qualifying world must have:

1. A stable public or reviewable entry point.
2. Meaningful interaction rather than passive playback.
3. A bounded setting, simulation, canon, mechanics, or rule system.
4. Persistent state or a reproducible configuration/version.
5. A material and describable AI role.
6. An identifiable creator, operator, or rights claimant.
7. Enough access and safety metadata to evaluate entry.

### Included examples

- interactive narrative or character worlds
- explorable AI-generated spatial environments
- persistent agent societies and simulations
- games or social experiences with material AI behavior
- training or research simulations with world state and agents

### Excluded from the World entity

- static AI images, video, audio, or prose
- a single-purpose assistant with no world context
- foundation models, prompts, datasets, and generic tools
- engines and platforms considered only as products
- unaddressable demos with no stable entry point
- marketing pages that describe a world but provide no experience or reproducible artifact

Platforms, engines, agents, characters, creators, organizations, assets, and IP should be linked entity types. They are not all Worlds.

## World Manifest v0

Define required, optional, derived, and verified fields across:

### Identity

- schema version
- canonical world ID and canonical URL
- name, summary, status, version, created/updated dates
- world type and modalities
- creator/operator and claimed owner

### Experience

- entry points and supported devices
- access requirements, pricing, availability, region, and age guidance
- interaction model
- persistence/reproducibility model
- supported languages

### World structure

- setting, lore/canon, rules/mechanics, state model
- agents and characters
- assets and dependencies
- platforms, engines, models, and protocols
- optional economy and governance descriptions

### AI role

- build-time versus runtime AI use
- generated or agent-controlled elements
- model/provider disclosures when known
- human-control and moderation boundaries

### Rights, trust, and safety

- license and commercial-use status
- IP/rightsholder declarations
- provenance and source evidence
- claim/verification status
- content/safety categories and moderation contact
- data/privacy considerations

### Discovery

- tags and structured facets
- representative media
- semantic description
- related worlds, inspirations, forks, imports, and dependencies
- primary calls to action: enter, play, integrate, contact, or request rights

Every extracted or derived field must support field-level provenance, confidence, and last-observed time. Unknown must remain unknown; the extractor must not invent missing values.

## Standards alignment

- Reuse A2A Agent Card fields for linked agents where applicable.
- Reference MCP server metadata rather than copying package/configuration data.
- Track C2PA Content Credentials for media provenance when available.
- Track glTF, USD, WebXR, and other interoperability claims as declared capabilities.
- Review the Metaverse Standards Forum “Web of Worlds” and universal-manifest work.
- Do not claim World Manifest v0 is an industry standard during this milestone.

## Acceptance criteria

- [ ] Qualification can be applied consistently by two reviewers.
- [ ] World, Platform, Agent/Character, Creator/Organization, and Asset/IP are distinct entity types.
- [ ] Required fields are minimal enough for independent creators.
- [ ] Optional economy and governance fields do not block MVP publication.
- [ ] JSON Schema validates positive fixtures and rejects negative structural fixtures.
- [ ] Unknown and undisclosed values cannot be represented as verified facts.
- [ ] Every factual field can retain source, confidence, verification state, and observation time.
- [ ] The schema supports versioning and backwards-compatible extension.
- [ ] A2A/MCP/C2PA overlap is reused or referenced rather than duplicated.
- [ ] No production database migration or public API is implemented in this issue.
