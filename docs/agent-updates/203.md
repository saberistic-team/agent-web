        # Docs update for #203

        Write the WorldGraph MVP PRD and phase roadmap

        ## Requested

        ## Summary

Convert the accepted market position, schema, corpus, journeys, and demand evidence into one buildable MVP PRD and a gated phase roadmap. This issue is the decision boundary between Product Definition and implementation.

## Proposed MVP scope

The PRD should evaluate and, if validation supports it, specify:

- curator/admin creation of a private World draft from a URL or structured submission
- source capture and field-level provenance
- assisted Manifest v0 extraction with unknown/confidence handling
- qualification, duplicate, rights, safety, and quality review
- creator claim and correction
- publish/unpublish and stale/reverification lifecycle
- public World profile and machine-readable manifest
- structured filters plus search over the validated pilot corpus
- primary actions: enter/play, integrate, source link, or creator contact
- privacy-preserving product analytics

## Explicit non-goals

Exclude from the MVP:

- world generation or hosting
- 3D rendering/runtime
- autonomous crawling of the open web
- tokens, wallets, or speculative assets
- transactions, marketplace escrow, or licensing contracts
- ratings, comments, and social feeds
- cross-world identity or agent migration
- governance execution
- consumer personalization
- paid placement
- declaring Manifest v0 an industry standard
- automatic publication of existing Project Brief records

## Required PRD sections

- executive decision and problem statement
- target users and jobs to be done
- evidence and validation summary
- product principles
- functional requirements
- trust, verification, provenance, rights, moderation, and dispute requirements
- accessibility and privacy requirements
- information architecture and journeys
- data/entity model at product level
- search and ranking requirements
- analytics and measurement plan
- rollout and operational plan
- dependencies, risks, and mitigations
- non-goals
- acceptance criteria
- open questions requiring owner decision

## Success framework

Define metrics in five groups:

1. **Supply activation:** eligible drafts reviewed, claimed, and published.
2. **Manifest quality:** required-field completeness, creator correction effort, factual disputes, and stale-field rate.
3. **Discovery success:** successful search tasks, useful-result selection, outbound entry/contact actions, and no-result rate.
4. **Retention:** creators maintaining profiles and discovery users returning for a recurring job.
5. **Guardrails:** rights disputes, unsafe listings, false verification, removals, and privacy incidents.

Set pilot targets from validation evidence; do not invent vanity targets without a baseline.

## Phase roadmap

Break later work into gated phases rather than committing the full vision:

- Phase 1: manifest, private drafts, and admin review
- Phase 2: creator claim and public profiles
- Phase 3: structured and semantic discovery
- Phase 4: relationship graph and developer API
- Phase 5: rights/licensing workflows only if demand is validated
- Future research: interoperability, economy, governance, and world-to-world actions

Only Phase 1 should be decomposed into engineering issues when this PRD is accepted.

- [ ] Every functional requirement has measurable acceptance criteria.
- [ ] Trust, rights, safety, disputes, and stale data are first-class requirements.
- [ ] Success metrics distinguish supply, quality, discovery, retention, and guardrails.
- [ ] Non-goals prevent the reality-protocol vision from entering MVP scope.
- [ ] Project Brief intake remains separate.
- [ ] The roadmap uses validation gates rather than fixed promises for later phases.
- [ ] Owner approval is recorded before implementation issues are generated.
- [ ] No production implementation is included in this issue.
